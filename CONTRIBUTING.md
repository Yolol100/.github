# Bijdragen

## Vooraf

- Controleer README, bestaande issues en repositoryspecifieke instructies.
- Open voor grotere wijzigingen eerst een issue met probleem, doel en voorgestelde grens.
- Deel geen secrets, klantdata, accountgegevens of privélogs.

## Werkwijze

1. Maak een korte branch vanaf de actuele default branch.
2. Beperk de wijziging tot één doel.
3. Voeg tests of reproduceerbaar bewijs toe.
4. Werk documentatie en changelog bij wanneer gedrag of releasegebruik verandert.
5. Open een pull request met risico, testresultaten en rollback.
6. Merge pas wanneer verplichte checks en review zijn afgerond.

## Kwaliteit

- Behoud bestaande publieke API's en runtimecontracten tenzij de wijziging ze expliciet migreert.
- Geef GitHub Actions alleen de minimaal noodzakelijke permissies.
- Pin externe Actions op een volledige commit-SHA.
- Commit geen generated artifacts tenzij de repository dit expliciet als releasebron voorschrijft.
- Beschrijf onzekerheid; presenteer labdata, scanners of transportstatus niet als inhoudelijke garantie.

## Licenties

Een publieke repository zonder expliciete open-sourcelicentie verleent geen algemene toestemming voor hergebruik, distributie of afgeleide werken. Bijdragen veranderen de bestaande licentiestatus niet automatisch.
